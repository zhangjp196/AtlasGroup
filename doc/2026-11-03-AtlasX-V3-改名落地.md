# AtlasX（V3）改名落地记录

> 2026-11-03 · 对应 `VERSION = 3.0.0`
> 决策依据：`doc/2026-11-01-Atlas-Group-改名与版本跳升分析.md`（三层拆分）与用户要求
> 「V3 版本调整，名称调整为 AtlasX，相关文档调整」。

## 1. 结论

产品显示名统一为 **AtlasX**，版本号跳到 **3.0.0**；**标识层保持 `Atlas` 旧名**。

| 层 | 处理 | 结果 |
| --- | --- | --- |
| 显示层 | 全部替换 | 窗口 / 菜单 / 通知、启动日志与终端提示、前端 `<title>` / 启动动画 / 侧栏 / 占位符 / 双语文案、系统提示词身份、默认角色名（新库）、诊断包与记忆导出文件名、`AtlasX.app` / `AtlasX-3.0.0.dmg` / `AtlasX.exe` |
| 标识层 | 保持不变 | 数据目录 `~/Library/Application Support/Atlas`、锁 `atlas.lock`、bundle id `com.aiplatform.atlas`、Keychain service `com.atlas.agentzero`、`.atlas/` 约定、`services/agent_zero`、`/api/agent-zero`、`ATLAS_HOME` / `ATLAS_DEBUG` / `ATLAS_SMOKE` |

标识层不改的原因：它们决定已有会话 / 附件 / 已保存 API Key / 用户工作区约定文件的
归属，以及签名、公证与更新识别。只改显示层，升级后数据与密钥原样可用。

## 2. 代码改动

### 2.1 品牌单一来源

- `services/agent_zero/version.py`
  - 新增 `APP_NAME = "AtlasX"`、`LEGACY_APP_NAME = "Atlas"`；
  - `APP_VERSION` 仍读根目录 `VERSION`（现为 `3.0.0`）。
- 后端引用 `APP_NAME`：`webapp.py`（标题 / 日志 / 终端提示）、`routes/app_routes.py`
  （`/app/info` 的 `name`）、`task_layer/prompt_builder.py`（身份兜底）、
  `task_layer/conversation.py`（角色兜底）、`stores/zero_store.py`（默认角色）、
  `services/diagnostics_service.py`（诊断包元数据与文件名）。
- `User-Agent` 统一为 `f"{APP_NAME}/{APP_VERSION}"`（`app_routes._user_agent()`、
  `runtime/zero/llm._request_headers`），修掉写死 `Atlas/2.0` 的旧问题。

### 2.2 前端

- `web/index.html`：`<title>`、启动动画、侧栏品牌、顶栏副标题、输入框占位改为
  `AtlasX`；静态资源缓存戳 `?v=3.0.0-1`。
- `web/assets/app.js`：
  - i18n 品牌名改成 `{app}` 占位，`t()` 统一注入 `appBrand()`；
  - `document.title`、默认角色名、头像名兜底都走 `appBrand()`（来源 `/app/info`
    的 `name`，兜底 `AtlasX`）；
  - 记忆导出文件名改为 `atlasx-memories.md`。
- `web/assets/app.css`：仅注释更新。

### 2.3 默认角色名迁移

- 新库：默认角色直接创建为 `AtlasX`。
- 旧库：默认角色仍叫 `Atlas`（用户没自定义过）时跟随改名；用户自定义过的名字不动。
- 旧会话消息里已落库的 `role_name` 保持原样，不回写历史。

### 2.4 打包

- `desktop/Atlas.spec` → `desktop/AtlasX.spec`：`name` / `COLLECT` / `BUNDLE` /
  `CFBundleName` / `CFBundleDisplayName` / 版权文案改为 AtlasX；`bundle_identifier`
  保持 `com.aiplatform.atlas`；图标文件仍是 `desktop/Atlas.icns`。
- `desktop/Atlas-windows.spec` → `desktop/AtlasX-windows.spec`：产物 `AtlasX.exe`。
- `desktop/build_macos.sh`：`dist/AtlasX.app`、`dist/AtlasX-<VERSION>.dmg`、
  `hdiutil -volname "AtlasX"`、codesign 路径同步。
- `desktop/build_windows.ps1`：`dist\AtlasX\AtlasX.exe`。
- `desktop/launcher.py`：`APP_NAME = "AtlasX"`（窗口 / 菜单 / 通知 / 报错）；
  新增 `APP_HOME_DIR = "Atlas"` 让数据目录继续落在旧路径。

### 2.5 文档

- `README.md`：标题改为 AtlasX、新增 3.0.0 条目与「命名与标识」章节，更新
  macOS / Windows 打包路径、数据目录说明、`User-Agent` 描述。
- `desktop/README.md`：品牌、产物名、数据目录说明、签名命令同步。
- 本文件：改名落地记录。

## 3. 测试

- 新增 `tests/unit/test_branding.py`：品牌常量 / `/app/info` / 默认角色迁移 /
  UA / 诊断包名 / 标识层不变 / 打包产物命名。
- 新增 `tests/js/branding_test.js`：静态品牌点、`{app}` 占位、缓存戳、版本、

## 4. 后续可选（P2）

如果确实要「连标识层一起改」，需要一次独立的发布：

1. 数据目录改名 + 一次性迁移（复制或移动 `/Application Support/Atlas` →
   `/Application Support/AtlasX`），并处理双实例锁（新旧锁名不同）；
2. bundle id / Keychain service 改名 = 重新注册身份：已存 API Key 需要用户重填，
   签名 / 公证链路要同步换；
3. `.atlas/` 约定目录改名会破坏用户工作区里已有的 commands / hooks / rules，
   需要兼容读旧路径或提供迁移命令；
4. `services/agent_zero`、`/api/agent-zero`、`config|data/agent_zero` 改名会波及
   约两千处引用，建议单独一次提交并全量回归。
