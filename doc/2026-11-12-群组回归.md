# 群组回归：从「会话私有参与角色」到共享群组（3.16.0）

> 3.12.0 曾移除群组入口，把多角色收敛为「主持角色 + 会话私有参与角色」。
> 3.16.0 按完整群组实体回归：群组是长期共享的花名册，会话绑定后实时共享，
> 群级永久授权、群工作区、群级工单重新有意义。

## 1. 结论

| 概念 | 载体 | 生命周期 |
| --- | --- | --- |
| 群组 | `agent_teams.kind='group'` | 长期；可绑定多条会话 |
| 会话私有参与角色 | `agent_teams.kind='participants'` | 跟随单条会话；`participants-*` |
| 会话 | `conversations.team_id` | 绑定群组或私有参与角色 |

- **群组是 live 实体**：改群名 / 头像 / 成员 / 模式 / 工作区，所有绑定会话立即生效，
  并写入 IM 系统消息。
- **会话私有参与角色保留**：不加入群组时仍可给单条会话加参与角色（含临时角色）。
- **编辑群聊成员会分叉**：在群聊里点「参与角色」并保存，会把当前会话从群组分叉成
  `participants-*`，群组和其他群聊不受影响；UI 保存前明确确认。
- **全局 Agent 永不加入群组**：保留 `create_conversation` / `bind_team` /
  `team_manage` 三层守卫。

## 2. 数据

`agent_teams` 新增：

| 列 | 说明 |
| --- | --- |
| `kind` | `group` = 用户可管理的群组；`participants` = 会话私有参与角色 |

- 旧库由 `_migrate_additive` 自动补列（默认 `group`），并按 `participants-%`
  前缀回填 `kind='participants'`。
- `/teams` 默认只返回 `kind='group'`；`?kind=all` 供前端会话侧解析私有参与角色。
- `/teams/{id}`、`PATCH`、`DELETE`、`bind`、`unbind` 对 `participants-*` 返回 404，
  避免从群组页误操作内部团队。

## 3. 语义

### 3.1 共享成员

- `conversations.team_id` 指向群组时，`_team_public` / `team_for_conv` 实时读取
  群组 leader + members。
- `update_team` 给所有 `bound_conversation_ids` 写系统消息：加人 / 退群 / 改模式 /
  改群名。
- 群组工作区变化时，绑定会话中「跟随」的会话同步迁移；`workspace_custom=1`
  的手动工作区保留。

### 3.2 群级永久授权

- `permission_scope_grants.scope='team'` 现在对应稳定群组 id，跨会话生效。
- 群资料抽屉列出该群的永久授权，可撤销；解散群组时同步清理授权。
- 审批卡片根据 `team.kind` 显示「永久（本群组）」或「永久（本会话）」。

### 3.3 群级工单

- 工单本就带 `team_id`；群资料里可新建群工单，工单页支持 `?team_id=` 过滤。
- 只有共享群组会挂到工单执行会话；`participants-*` 会被忽略，避免把工单执行会话
  绑到另一条会话的私有团队。

### 3.4 会话分叉

- 分支共享群聊：继续绑定同一群组（live）。
- 分支私有参与角色：复制一份新的 `participants-<新会话>-*`，不能与原会话共用。

## 4. 界面

- 左轨「群组」入口 + `/group`、`/group/:id`。
- 群组页：群卡（群名 / 模式 / 成员 / 绑定会话数 / 在办工单 / token 合计）、搜索、
  右键打开群聊 / 群资料 / 群工单 / 解散。
- 群资料抽屉：群名 / 头像 / 介绍 / 成员与群主 / 协作方式 / 圆桌上限 / 工作区 /
  绑定会话 / 群级永久授权 / 解散。
- 新建会话：可选「群聊」优先于单聊；已有群聊会话直接复用，没有就开草稿，
  发出第一条消息才落库。
- 会话管理：可绑定 / 解绑群组；绑定后成员由群组维护，角色 / 临时角色区域隐藏。
- 聊天头部：群聊显示「群资料」按钮，改名落到群组；普通会话仍用「参与角色」。
