# 考勤薪酬自动化产品需求文档（PRD）

| 文档属性 | 内容 |
| --- | --- |
| 版本 | V1.0（需求草案） |
| 状态 | 待业务确认 |
| 日期 | 2026-11-14 |
| 产品范围 | 中小企业考勤自动核算及薪酬核算衔接 |

> 本文依据现有业务讨论材料整理。带有“待确认”的规则、时间与交互细节，需要在开发排期前由业务方确认。考勤和薪酬结果必须由企业确认的规则计算；AI 仅提供辅助建议，不作为金额或员工处理结论的决策主体。

## 1. 产品背景

中小企业通常从钉钉等平台导出考勤记录，再由 HR 手工整理、计算工时并逐条核对缺卡、迟到等异常。以 300 多人的企业为例，材料中估算 HR 每月可能需要约 10 天处理考勤数据。数据格式杂乱、规则特殊、员工反馈分散，容易造成重复劳动、错算、工资发放后更正及员工投诉。

本产品通过数据导入与清洗、企业规则引擎、异常处理和员工自助核对，生成可追溯的考勤结果，并在后续阶段将已确认的考勤结果提供给薪酬核算流程。

## 2. 产品目标与成功指标

### 2.1 产品目标

1. 将考勤数据处理从人工表格操作转为可配置、可重复执行的系统流程。
2. 让考勤结果可追溯到原始记录、适用规则和处理记录，减少错误和发薪后返工。
3. 通过个人化异常通知和补卡反馈入口，提高员工按期核对效率。
4. 首期聚焦考勤核算；后续衔接绩效与薪酬项目，推动整体工资核算周期控制在 2 天内。

### 2.2 成功指标

| 指标 | 目标 | 统计口径 |
| --- | --- | --- |
| 考勤处理周期 | 目标 2 天内；流程稳定后争取第 1 天完成计算、次日早上生成报告 | 从本期数据处理启动到考勤报告生成 |
| 人工处理时长 | 相比试点前下降 | HR 每月用于导出、整理、核算和逐条核对的工时 |
| 考勤结果差异 | 通过历史数据对照验收，差异可解释并闭环 | 系统结果与 HR 确认基准结果的差异项及原因 |
| 员工核对效率 | 提高按期完成核对比例 | 已按期确认或提交反馈的员工数 / 应核对员工数 |
| 发薪后更正 | 减少因考勤错算引起的更正 | 每月因考勤计算错误产生的薪酬更正次数 |

“100% 准确”属于业务期望，不作为未经数据验收的产品保证。具体基线、统计周期和达标阈值待试点前确认。

## 3. 用户角色

| 角色 | 主要诉求 | 权限范围 |
| --- | --- | --- |
| 企业管理员 | 配置组织、人员、考勤规则和核算周期 | 管理企业级配置；授权规则维护及审批人员 |
| HR / 考勤专员 | 导入数据、处理异常、核对结果、生成报告 | 查看授权组织的数据；处理异常；发起核算和导出 |
| 部门主管 / 审批人 | 确认本部门异常、补卡或特殊情况 | 查看并审批授权范围内的待办事项 |
| 员工 | 查看本人考勤、补充说明或申请补卡 | 仅查看本人记录并提交反馈 |
| 薪酬专员 | 接收确认后的考勤核算明细 | 查看薪酬核算所需字段；不默认拥有规则修改权限 |

## 4. 产品范围

### 4.1 首期范围（P0：考勤核算）

- Excel 导入考勤原始数据及必要的人员、班次信息。
- 数据格式校验、清洗、重复记录和异常记录识别。
- 配置并执行企业考勤规则，生成个人及汇总考勤结果。
- 异常列表、员工个人通知、补卡或说明提交、HR 复核与结果锁定。
- 考勤报告导出，以及规则版本、计算明细和操作记录追溯。

### 4.2 后续范围（P1：薪酬衔接）

- 将已确认的考勤结果映射为薪酬核算所需项目和明细。
- 接入绩效数据或其他薪酬输入，支持企业确认的岗位或组织差异规则。
- 输出可复核的薪酬核算明细，支持薪酬专员复核及导出。

### 4.3 不在本 PRD 范围

- 完整 ERP、人事主数据、招聘、生产管理或 BOM 系统。
- 销售定价、商业模式和 SaaS 收费策略。
- 未经企业授权的自动扣款、自动旷工认定或自动发薪。

## 5. 核心业务流程

1. HR 创建核算周期并导入考勤文件。
2. 系统检查文件结构、字段、人员匹配、重复记录和缺失数据，并返回导入结果。
3. HR 处理无法自动修复的数据问题，确认后启动考勤计算。
4. 系统根据核算周期适用的规则版本计算考勤结果，并生成异常待办。
5. 对确定性异常，系统按已批准规则计算；对缺卡原因不明、记录冲突或规则未覆盖的情况，暂停相关结论并转待确认。
6. 系统向员工推送个人考勤摘要和待处理异常。员工查看记录、提交补卡或说明；主管或 HR 按权限审批。
7. HR 复核异常、查看计算依据并锁定本期考勤结果。
8. 系统生成考勤报告。后续阶段将锁定结果映射至薪酬核算流程，完成复核后导出薪酬明细。

## 6. 功能需求

优先级说明：P0 为首期必须交付；P1 为薪酬衔接阶段；P2 为体验或自动化增强项。

### 6.1 数据导入与校验

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| FR-01 | P0 | 支持按模板导入 Excel 考勤数据 | 用户可下载模板；系统校验必填字段、格式和数据类型；导入后显示成功、失败和跳过数量 |
| FR-02 | P0 | 支持员工标识匹配 | 无法匹配的记录进入错误清单，显示原始行及原因；未解决前不能进入正式计算 |
| FR-03 | P0 | 检查重复、缺失及明显冲突数据 | 系统标记疑似重复、缺失时间、冲突打卡等记录；保留源文件与原始行供追溯 |
| FR-04 | P1 | 支持从钉钉等平台自动获取数据 | 接口、授权范围、同步频率及失败重试策略待平台接入方案确认 |

### 6.2 考勤规则配置与计算

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| FR-05 | P0 | 管理员可配置班次及打卡规则 | 可表达经确认的一日多次打卡、班中休息打卡、跨日班次及打卡时间窗口；配置结果可预览 |
| FR-06 | P0 | 管理员可配置迟到、早退、缺卡、请假、加班和工时计算规则 | 每条规则具备适用范围、生效日期和版本；未配置的规则不得静默套用默认扣款 |
| FR-07 | P0 | 按指定规则版本计算考勤 | 每条结果展示原始记录、规则版本、计算步骤和结果；同一输入与规则版本重复计算结果一致 |
| FR-08 | P0 | 支持规则变更后的影响预览 | 规则发布前可查看受影响组织、员工及核算周期；已锁定周期不得被静默重算 |
| FR-09 | P1 | 支持考勤项目映射薪酬项目 | 可配置考勤结果到薪酬项目的映射；导出明细含来源考勤项目、映射规则和计算值 |
| FR-10 | P1 | 支持绩效及岗位差异数据参与薪酬核算 | 能按已确认的输入字段和规则生成明细；缺少输入或规则冲突时提示并阻止最终确认 |

### 6.3 异常处理与员工核对

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| FR-11 | P0 | 提供异常待办列表 | 可按周期、部门、员工、异常类型和状态筛选；每条异常显示日期、原始记录、规则依据和当前处理人 |
| FR-12 | P0 | 对可确定异常应用已批准规则 | 仅在规则明确且数据完整时自动计算；无法判断时进入待确认，不自动认定旷工或扣款 |
| FR-13 | P0 | 向员工推送个人考勤信息 | 员工只收到本人摘要及待办；通知渠道和发送时机可配置，默认不得群发其他员工明细 |
| FR-14 | P0 | 员工可提交补卡申请或情况说明 | 提交内容与关联原始记录绑定；提交后进入待审批状态，并可查看处理进度 |
| FR-15 | P0 | 主管或 HR 可审批、驳回或要求补充材料 | 每次处理记录处理人、时间、意见和状态变更；审批通过后系统重算受影响结果 |
| FR-16 | P0 | 支持反馈期限和提醒 | 管理员可配置反馈期限；系统对未处理事项提醒员工，并将逾期事项展示给 HR |

### 6.4 复核、报告与薪酬输出

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| FR-17 | P0 | HR 可复核并锁定考勤周期 | 锁定前展示未处理异常和数据错误；存在阻断项时不能锁定，或需授权人员填写原因后例外锁定 |
| FR-18 | P0 | 生成考勤报告 | 报告可按员工和组织汇总，包含出勤、工时、异常及处理状态；导出结果与页面核算版本一致 |
| FR-19 | P0 | 支持经授权的更正和重新计算 | 锁定后修改需授权；记录更正原因、修改人、时间及前后差异，并生成新版本 |
| FR-20 | P1 | 生成薪酬核算明细 | 仅使用已锁定考勤结果；显示薪酬项目、输入来源、规则版本和计算明细；未经薪酬专员确认不得标记为最终结果 |

### 6.5 AI 辅助能力

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| FR-21 | P2 | AI 辅助识别非结构化备注、归类异常或生成通知草稿 | AI 输出明确标记为建议；用户可采纳、修改或驳回；不得直接改变考勤或薪酬最终值 |
| FR-22 | P2 | 对低置信度或涉及金额的建议转人工处理 | 系统不自动执行该建议；在记录中保留建议内容及人工处理结果 |

## 7. 关键状态与业务约束

### 7.1 核算周期状态

`草稿 → 数据已导入 → 待处理数据错误 → 待计算 → 计算中 → 待员工核对 / HR 复核 → 已锁定 → 已导出`

计算失败或导入失败时保留错误信息，并允许授权用户修正后重试。锁定周期的结果不可被后台任务静默覆盖。

### 7.2 异常状态

`待员工反馈 → 待审批 → 已通过 / 已驳回 / 待补充 → 已重算并关闭`

企业可针对无需员工反馈的异常配置处理流程，但系统必须保留处理依据和操作记录。

### 7.3 薪酬结果约束

- 薪酬核算读取已锁定的考勤结果和已确认的薪酬规则。
- 规则缺失、输入数据不完整或结果无法解释时，进入待复核状态。
- 系统仅生成核算明细；是否发薪由企业现有授权流程决定。

## 8. 数据与权限要求

### 8.1 数据范围

首期所需数据包括员工唯一标识、组织信息、班次、原始打卡时间、请假与加班记录，以及企业确认的规则字段。薪酬阶段再按最小必要原则增加薪酬项目、绩效或岗位差异数据。

### 8.2 权限要求

- 员工只可查看本人数据和本人处理状态。
- 主管只能查看授权组织内的数据和审批事项。
- HR 按授权范围导入、核算、处理异常和导出。
- 规则维护、规则审批、周期锁定和更正权限可分开配置。
- 薪酬数据按独立权限控制，默认不向无关员工或主管开放。

### 8.3 审计要求

系统需记录文件导入、规则创建与变更、计算启动、审批、锁定、重算和导出操作，至少包含操作者、时间、对象、操作前后差异及操作原因（适用时）。数据保留期限和删除规则待企业确认。

## 9. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 可解释性 | 任何考勤或薪酬结果均可查看输入、规则版本和计算明细 |
| 一致性 | 相同数据、规则版本和计算版本应产生一致结果；重算不得覆盖旧版本记录 |
| 安全性 | 按角色和组织范围授权，敏感薪酬数据受独立权限控制 |
| 可恢复性 | 导入或计算失败时保留失败原因，支持修复后重试，不产生重复结果 |
| 性能 | 以约 300 人试点数据验证处理周期；更大数据量下的容量目标待实际数据量和部署方式确认 |
| 通知 | 通知渠道、发送时段和重试策略待企业及平台接入方式确认 |

## 10. 试点与验收

首期建议以现有真实考勤数据开展试点，材料中提及的约 300 人规模可作为验证参考。试点至少覆盖正常打卡、一天多次打卡、班中休息打卡、迟到早退、缺卡、请假、加班、跨日班次和人工更正场景。

验收步骤：

1. 由 HR 提供一段完整核算周期的数据、当前人工核算结果及适用规则。
2. 系统导入并计算，逐项与 HR 确认的基准结果对比。
3. 对差异逐条归因，区分原始数据问题、规则配置问题和系统计算问题；修正规则后重新验证。
4. 检查员工反馈、审批、锁定、重算、导出和审计记录是否完整。
5. 业务方确认差异阈值、周期目标和遗留项后，决定是否扩大试点或进入薪酬衔接阶段。

## 11. 依赖与待确认事项

1. 首期数据来源及文件模板：钉钉导出文件格式、字段稳定性和是否需要 API 接入。
2. 考勤规则清单：班次、打卡次数、迟到早退、缺卡、补卡、请假、加班、工时及跨日计算规则。
3. 规则治理：规则由谁维护、谁审批、何时生效，以及历史周期是否允许重算。
4. 员工交互渠道：钉钉机器人、员工端或其他渠道；通知、审批和补卡能力依赖对应平台权限。
5. 周期目标口径：数据处理从何时开始计时，节假日如何计算，报告完成的定义是什么。
6. 薪酬阶段：薪酬项目、绩效数据来源、岗位差异规则、导出格式及现有发薪系统接口。
7. 权限、数据保存期限和员工个人信息处理要求。
8. 试点验收阈值：允许差异范围、抽样方式、人工基准结果责任人及扩大上线条件。
