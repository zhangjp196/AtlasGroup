# 角色任务与子代理（3.11.0）

> 目标：角色会话与群组会话里，**一个角色可以同时并行推进多项任务**；**单个任务内部还能再派子代理**。任务与对话仍然分离：过程不进转录，结果回到对话。

## 1. 能力边界

| 场景 | 谁执行 | 入口 | 并行方式 |
| --- | --- | --- | --- |
| 角色会话 · 本角色的多项独立任务 | 当前角色 | `background_task.tasks[]` | 每条任务一个 `team_task` + 一个成员 run，worker 并行认领 |
| 群组会话 · 主持自己的独立任务 | 主持角色 | `background_task.tasks[]` | 同上（主持 run 与成员 run 可并存） |
| 群组会话 · 多成员协作 | 各成员 | `plan{op:"delegate", target:"team", assignments[]}` | 一个 `team_task` 下多个成员 run 并行 |
| 群组会话 · 同一成员多件活 | 同一成员 | 同一 `assignments[]` 里出现多条 | 多个成员 run 并行；画布节点 id 带序号，不会互相覆盖 |
| 单个任务内部拆分 | 子代理 | `plan{op:"delegate", target:"subagent", assignments[]}` | `asyncio.gather` 并发；每个子代理独立事件流 |

## 2. 后台任务批量派发

`background_task` 由对话层注入（不在 registry / 工具包里），角色会话与群组主持都可见。

```json
{
  "name": "background_task",
  "arguments": {
    "tasks": [
      {"goal": "补齐用户表索引", "title": "索引"},
      {"goal": "整理接口文档", "title": "文档"}
    ]
  }
}
```

- 每项 `{goal, title?, context?}` 建一条独立 `team_tasks`，各带一个成员 run；
- 单次最多 8 条（`MAX_BACKGROUND_TASKS_PER_CALL`），防止模型一次打满队列；
- 仍兼容旧的单任务调用：`{goal, title?, context?}`；
- 调用后本轮收尾：`_team_delegated=True`，下一轮工具清单被清空，避免主持在前台重复执行；
- 结果进入任务浮窗 / 执行画布 / 工单面板；每条任务独立完成、独立自动交回。

## 3. 任务内子代理

`delegate` 的解析规则（`packs._translate_merged`）：

1. `target=subagent` → `call_subagent`（即使带 `assignments`，也**不会**被误判成团队任务）；
2. `target=team` / `member_id` / `member_name` / 无 target 的 `assignments` → `call_team`；
3. 其余 → `call_subagent`。

单任务内的并行子代理：

```json
{
  "name": "plan",
  "arguments": {
    "op": "delegate",
    "target": "subagent",
    "assignments": [
      {"goal": "读现有索引定义", "name": "调研员"},
      {"goal": "写迁移脚本", "name": "工程师", "context": "只改 sql/"}
    ]
  }
}
```

- 每个子代理继承父角色模型与工具白名单，可用 `tools` 继续收窄；
- 子代理不继承父对话历史，只收到 `goal / instructions / context`；
- 并发执行（`asyncio.gather`），事件写进父 run 的 `subagent_event`，`call_id` 为
  `<原 call_id>#<序号>`；
- 返回值：`output`（合并文本）、`outputs[]`（每个子代理的结论 / 错误）、
  `display.agents[]`（每个子代理的展示载荷）；单子代理仍返回旧的 `display` 结构。

## 4. 任务成员的约束

任务成员 run（`conversation_runs.team_task_id` 非空）会：

- 追加 `prompt_builder.TASK_MEMBER` 提示：只完成当前任务，内部可派子代理；
- 不再下发 `background_task`，避免任务再生任务；
- `call_team` 被拒绝（读当前 run 的 `team_task_id` 判断），提示改用
  `delegate target=subagent`；子代理仍可用。

这样「一个任务」是并行拆分的最小单位，不会无限套娃，也不会绕过任务归属。

## 5. 执行画布

- 后台任务视图：成员节点按任务成员 run 展示；同一角色多条任务用序号区分 id；
- 任务内子代理：后端 `graph_service._member_run_nodes` 把成员 run 的
  `subagent_event` 聚合成 `kind=subagent` 节点，`parent_id` 指向该成员节点；
- 前端 `AgentCanvas.buildTaskFlow` 在成员节点右侧渲染子代理节点与连线。
