## 1. 一句话定位

V3 是 **AtlasX**，目标是 **QQ 式 IM 机制 + 统一的面板 UI**：**左边会话列表 + 右边聊天窗**
是全部骨架；文件、diff、进程、任务、记忆都是**会话内的卡片**或**点开才出现的抽屉**。
对话是唯一入口，工程能力是对话的附件；多角色用「群」表达（团队 = 群，角色 = 人）。
完整目标与「不做清单」见 [目标与收尾](2026-11-03-AtlasX-V3-目标与收尾.md) §1–§3。

## 4. 阶段规划

### P1 · 团队 / 群聊统一（核心）—— ✅ 已完成（2026-11-03）

**目标**：团队成为唯一多角色机制，群聊在 IM 里可创建、可编辑、可绑定、可对话。

1. ✅ **Schema（增量加列，不重建库）**
   - `agent_teams` 补 `mode`（`orchestrate` / `roundtable` / `single`，默认 `orchestrate`）与
     `max_speakers`（默认 4，上限 12）；现有 `_migrate_additive` 会自动补列。
   - 已做 `roles.model_code`（成员可用自己的模型档案）；`roles.team_id` / `roles.is_system`
     与 `workspaces.default_team_id` 暂不做（归属共享与删除语义留到 P4 一起定）。
2. ✅ **惰性归一（保留旧数据）**
   - 首次访问（`GET /teams`）或第一次对话时：工作区若有 `host_role_id` /
     `member_role_ids`，合成一个确定性默认团队（`team-default-<ws>`，
     mode=`orchestrate`，leader=host，members=其余），幂等且不覆盖用户后来的修改。
   - 会话没有 `team_id` 但工作区有群组信息时自动绑定；之后 `_team_roles` 只读团队，
     不再直接读 `workspaces` 群列（旧列先停写，3.1 再删）。
3. ✅ **执行路由**
   - `_stream_role`：`team.mode == orchestrate` → 主持单角色（现有行为）；
     `roundtable` → `_group_reply_stream(team)`；`single` → 指定角色。
   - `GROUP_MAX_SPEAKERS` 与 `_MAX_MEMBERS` 合并为 `agent_teams.max_speakers` + 全局上限。
4. ✅ **角色包络差异化**
   - `team_service._ensure_role` 接受 `envelope` / `model_code`，未知工具不落库；
   - `delegate` 的 `tools` 对团队成员生效（与成员包络取交集，只收窄不放宽）；
   - `roster_text` 区分主持 / 成员视角，并列出成员工具子集与模型。
5. ✅ **REST（新增 `routes/team_routes.py`）**

   ```
   GET    /teams?workspace_id=...
   POST   /teams
   GET    /teams/{id}
   PATCH  /teams/{id}        name / description / mode / leader / members
   DELETE /teams/{id}        解绑会话 + 删非系统角色
   POST   /teams/{id}/bind   {conversation_id}
   POST   /teams/{id}/unbind {conversation_id}
   GET    /conversations/{id}/team
   ```

   权限：UI 走 REST 直接执行；只有模型 `team_manage(create)` 保留强制人工确认。
6. ✅ **测试**：`tests/unit/test_team_modes.py`（三种 mode 路由）、
   `tests/integration/test_team_routes.py`（CRUD / bind / 删除解绑）。

**验收**：通过 REST 建群 → 选主持与成员 → 绑定会话（界面入口在 P2）；`roundtable`
下成员能各自应答、`@成员` 能点名；`orchestrate` 下成员活动出现在委派卡片；
删团队解绑会话。**共享角色不误删**仍未做（P4 风险项）。

### P2 · 会话信息抽屉 + IM 主路径 —— ✅ 已完成（2026-11-03）

1. ✅ **会话信息抽屉**（`side-drawer`）：群名 / 简介 / 协作模式 / 成员（头像 + 专长 +
   工具子集，可增删）/ 工作区 / 模型；启用现有 40 条 `team.*` i18n。**不做设置页团队 tab。**
   面板的布局 / 开合 / 固定状态统一进「设置 → 外观」，与主题、语言、dock 侧别同一入口。
2. ✅ **顶栏收敛**：workspace / vcs / codegraph / mem 收进抽屉；保留任务与进程入口
   （输入框上方的 chip / 对话内卡片）。
3. ✅ **新建会话选「单聊 / 群聊」**：单聊 = 选角色（`single`）；群聊 = 选团队
   （默认 `orchestrate`，可切 `roundtable`）。
4. ✅ **`@成员` 补全 + `mentions` 打通**：`updateSlashMenu` 支持 `@` 触发、列出群成员；
   `MessageBody` 加 `mentions`；`_group_reply_stream` 按 mentions 决定谁先说话。
5. ✅ **进群系统消息**：`by='system'` 的 fact（「主持把「后端」加入群聊」），比配置面板更符合 IM 心智。
6. ✅ **列表行 IM 化**：头像（团队/角色色块或首字）+ 最后一条消息预览 + 未读红点。
   未读用 `conversations.last_read_at`（增量加列），**打开会话时更新**，不在消息到达时写，
   避免与 `claim_run` 的写锁争用。
7. ✅ **工具调用卡片化**：默认折叠成一行；写文件 / diff / 命令失败默认展开；
   `panel-viewer` 去掉编辑态，改只读预览 + 复制（写文件交给工具调用）。

**验收**：收起右侧 dock 后仍能完成「看文件 / 看 diff / 看进程 / 看任务」；
列表能一眼看出谁在跑、有多少未读；群资料能改模式与成员。

### P2.5 · 工程能力收进对话（收尾）

- 进程面板与 `subagentBar` chip 统一成一种「进程卡片」；
- 工具调用徽标与 diff / 文件卡片同一套折叠语义；
- 空态与首次使用引导按 IM 语义重写（不再出现「工作台 / 面板」措辞）。

### P3 · 标识层清理（可选，独立发布）

- 数据目录 / 锁 / bundle id / Keychain service / `.atlas/` / 模块与 API 路径改名，
  含一次性数据迁移与双锁兼容；
- 涉及约 2079 处 `agent_zero` 引用 + 26 处 `.atlas` 引用，单独提交并全量回归；
- 需要重新签名 / 公证，已存 API Key 需用户重填。

**建议**：除非有分发/品牌硬需求，否则不做；当前「显示层 AtlasX、标识层 Atlas」已经够用。

### P4 · 打磨 —— ✅ 已完成（2026-11-03，后续拆分属可选优化）

- ✅ **`_stream_role` 拆分（两阶段）**：`_prepare_role_run` 抽出「模型 / 团队 / 目标 /
  提示词 / 历史 / 工具清单」组装；`_await_tool_approval` 抽出审批创建后的等待 + 心跳 +
  决定回写（两处调用共用）。循环内的工具分发仍可继续拆，属后续可选优化。
- ✅ 子代理深度文案与 `_SUBAGENT_MAX_DEPTH = 0` 对齐（不再声称不能嵌套）。
- ✅ PG 兼容函数清理：`jsonb_set` / `to_jsonb` 全部改为 sqlite `json_set`，删除注册。
- ✅ 上限收敛：`agent_teams.max_speakers`（1–12，默认 4）按团队生效；成员上限 12；
  并发 run / 重试 / 预算均走 `config.yaml`，接口与工具 schema 同源。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| `roundtable` 成本 | 一条消息最多 `max_speakers` 次完整工具循环 | 群里明示「本群 N 个角色，每条最多 N 次调用」；默认 `orchestrate` |
| 未读写入放大 | SQLite 写锁与 `claim_run` 争用 | 只在「打开会话」时更新 `last_read_at`，不按消息到达写 |
| 角色删除语义 | 共享角色被某个团队删除 | ✅ 删除前检查其它团队 / 会话 / 工作区引用；系统角色不删 |
| IM 化削弱重度工作流 | 文件/diff 要多点一层 | 抽屉支持「固定展开」，记住用户偏好 |
| `_stream_role` 过大 | 每改一处要通读千行 | 已拆出准备逻辑与审批等待；循环内工具分发仍可继续拆（非阻塞） |
| 旧库与代码再次漂移 | 启动失败 / 随机报错 | 保持 ORM 与真实 SQL 一致；`test_db_resilience` + 旧库副本演练纳入 CI 手工步骤 |
