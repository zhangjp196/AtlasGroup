# AtlasX V3：目标与收尾（定稿）

> 状态：**定稿**（2026-11-03）· 适用版本：`VERSION >= 3.0.0`（当前 3.1.0）
> 本文是 V3 的**目标、范围与口径**的唯一权威来源；执行细节见
> [AtlasX V3 路线图](2026-11-03-AtlasX-V3-路线图.md)，历史分析见 §7 文档地图。
> 文档收尾的含义：此前的待决策项全部关闭，后续实现不再需要重新讨论方向。

## 1. 一句话目标

**V3 = AtlasX 的 IM 形态：像 QQ 一样的 IM 机制 + 统一的面板 UI。**

- **IM 机制**：左边会话列表、右边聊天窗；单聊 / 群聊、群成员、`@成员`、未读、进群系统消息；
  对话是唯一入口。
- **面板 UI**：文件、diff、进程、任务、记忆、代码图谱都收进**会话内的卡片**或**点开的抽屉**；
  右侧 dock 不再常驻；面板的布局、开合、固定状态统一在「外观 / 面板」设置里管理。

一句话：**对话是唯一入口，工程能力是对话的附件。**

## 2. 两条支柱

### 2.1 IM 机制（机制层）

| 能力 | 要求 |
| --- | --- |
| 会话列表 | 头像 + 标题 + 最后一条消息预览 + 相对时间 + 进行中圆点 + 未读红点 |
| 单聊 | 选一个角色，按 `single` 执行 |
| 群聊 | 选一个团队（= 群），默认 `orchestrate`（主持说话、成员在委派卡片里干活），可切 `roundtable`（多头像各自应答） |
| 群资料 | 点会话标题打开「会话信息」抽屉：群名 / 简介 / 协作模式 / 成员（专长 + 工具子集）/ 工作区 / 模型 |
| 群成员 | 可增删成员；角色能力包络可差异化；删除团队要处理共享角色 |
| `@成员` | 输入框 `@` 补全群成员；`mentions` 从输入 → 落库 → 路由全链路打通 |
| 系统消息 | 进群/加人/改模式写成 `by='system'` 的对话记录，而不是配置提示 |
| 未读 | `conversations.last_read_at`；**打开会话时更新**，不按消息到达写 |

### 2.2 面板 UI（界面层）

| 能力 | 要求 |
| --- | --- |
| 右侧 dock | 不再常驻；面板从会话内卡片 / 会话信息抽屉进入，支持「固定展开」并记住偏好 |
| 会话信息抽屉 | 新增 `panel-conv`：群资料、与会者、工作区、运行设置；顶栏图标收进这里 |
| 卡片 | 工具调用默认折叠成一行；写文件 / diff / 命令失败 / 任务清单默认可见 |
| 抽屉 | 文件预览、diff、记忆、代码图谱统一为抽屉；viewer 去编辑态，只读预览 + 复制 |
| 设置 | 「设置 → 外观」统一管布局：主题、语言、dock 侧别、面板开合/固定、浮动卡片位置 |
| 上下文行 | 进程 / 任务 / 目标 以输入框上方的 chip 表达，跑完自动消失；不占正文宽度 |

## 3. 范围

### 3.1 V3 要做

- 团队 / 群聊统一（`agent_teams` 成为唯一多角色机制，`mode` + `max_speakers`）。
- 群资料抽屉 + 团队 REST（CRUD / bind / unbind）。
- 会话列表 IM 化（头像 / 预览 / 未读）。
- `@成员` + `mentions` + 进群系统消息。
- 面板 UI 收敛：dock 非常驻、卡片/抽屉统一、设置入口统一。
- `_stream_role` 机械拆分（无行为变化）与相关打磨。

### 3.2 V3 明确不做

- **不做 vibecoding 工作台**：不要「文件树 + 代码编辑器 + 终端 + diff 三栏并排」，
  不要常驻 IDE 侧边栏，不以「工程 / 分支」组织界面。
- **不做计划流程图**：进度只由任务清单承载（计划流程已下线，见 2.4.8）。
- **不把团队配置塞进设置页**：团队是「群」，入口是群资料 / 会话信息抽屉。
- **不做多租户 / 登录 / RBAC**：仍是本地单用户、回环监听。
- **不在 V3 排期做标识层改名**（见 §4 第 6 条）。

## 4. 已定口径（不再待决）

1. **群 = 团队，角色 = 人**。`workspaces` 只作对话容器（`root_path` 决定纯聊天工作区）；
   成员归属由 `agent_teams` 表达。
2. **保留旧数据**：新增列用增量迁移 + 惰性归一（工作区 host/member → 默认团队，会话自动绑定），
   **不重建库**。`workspaces` 的群组列先停写、归一，确认无读后再删（放到 3.1）。
3. **群聊默认 `orchestrate`**；`roundtable` 在群资料里手动切换；`single` 只用于单聊。
4. **面板 UI**：右侧 dock 不再常驻；会话信息抽屉是唯一的面板入口；
   用户可「固定展开」，偏好写入 UI 设置。
5. **进度**：任务清单（`todo_write`）是唯一进度载体；计划流程不再恢复。
6. **品牌**：显示层 **AtlasX**；标识层（数据目录、锁、bundle id、Keychain、`.atlas/`、
   `agent_zero` 模块与 `/api/agent-zero`）保持 **Atlas** 旧名，P3 改名不排期。
7. **未读**：用 `conversations.last_read_at`，只在打开会话时更新，避免与 `claim_run` 写锁争用。
8. **质量门槛**：`bash devops/ci.sh` 全绿（compileall + ruff + pytest + `node --check` +
   前端结构测试；4 组需 Chrome 的布局实测在有 Chrome 的环境跑）。

## 8. V3 完成定义（Done Definition）

满足以下可演示场景，V3 才算完成：

1. 新建群聊：选主持 + 成员 → 建群 → 发消息，主持按 `orchestrate` 执行，成员活动在委派卡片可见。
2. 切到 `roundtable`：`@后端` 能让成员单独应答，消息气泡带角色名。
3. 会话信息抽屉：能看到/修改群名、模式、成员、工作区、模型，改动即时生效。
4. 会话列表：每行有头像、最后一条消息、进行中圆点、未读红点；打开后未读清零。
5. 收起右侧 dock 后：从对话内卡片 / 抽屉完成「看文件、看 diff、看进程、看任务」。
6. 旧数据升级：启动即用，不重建库；默认角色自动跟品牌名，用户自定义的不动。
