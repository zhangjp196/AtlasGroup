# 执行画布：DAG 与子代理进度（3.6.0）

参考 Superagent / 多代理工作台的做法：不只显示「谁在说话」，而是显示**这一轮工作是怎么被分出去、执行到哪一步、哪里需要人**。

## 入口

- 会话顶栏的「执行画布」图标。
- 会话「更多」菜单 →「执行画布…」。
- 打开后覆盖整个工作区；顶部可刷新、过滤、缩放、回放、关闭。

## 图结构

- 根节点：主代理 / 群组主持。
- 团队成员节点：群组成员，默认「待命」，被委派后由子代理事件接管。
- 子代理节点：`call_subagent` / `delegate` / `call_team` 派生的子代理。
- 任务内子代理（3.11.0）：后台任务成员 run 的 `subagent_event` 挂在对应成员节点下，
  形成「主持 → 成员 → 子代理」三层；同一角色同时接多项任务时按成员 run 分节点。
- 连线：根节点 → 团队成员 / 子代理，成员节点 → 任务内子代理；运行中的边为流动
  虚线，失败的边为红色虚线。

节点卡片包含：

- 名称 / 主代理 / 团队成员 / 子代理
- 运行中 / 排队中 / 完成 / 失败 / 待命
- 目标或专长
- 进度条
- 工具数、耗时、根节点 token 总量
- 当前工具或最近输出片段

## 数据来源

`GET /conversations/{id}/graph`：

1. 当前 / 最近一次 run 的 `subagent_event`
   - 工具调用 / 工具结果
   - 进度文本
   - done / error
   - 新增 `ts`，用于活动时间与耗时
2. 已完成消息 trace 里的 `display.type=subagent`
   - 刷新后、事件过期后的历史兜底
3. 团队信息：leader + members，用于画出「待命」成员和团队边
4. 会话用量：token 总量
5. 当日运行数 / 完成数

前端每 2 秒刷新一次；收到当前会话的 `subagent_event` 时额外做一次 250ms 防抖刷新，保证工具切换和进度更新及时。

## 活动侧栏

- 最近活动：工具调用 / 工具结果 / 进展 / 完成 / 失败，按时间倒序
- 即将：当前会话排队的 run
- 刚刚发生：最近 5 条
- 点击节点会过滤活动；回放会按时间顺序依次高亮代理节点

## 边界

- 子代理事件本身只带 `call_id`，没有显式父子链；3.11.0 通过「事件属于哪条 run」补出
  任务内父子关系（成员 run → 子代理），主持 run 下仍是「根 → 子代理」一层。
  更深层的子代理如果需要完整树形展开，后续在事件里补 `parent_call_id` 即可。
- 每个子代理的 token / 成本没有单独计费；根节点显示会话总量，子节点显示工具数与耗时。
- 回放是活动级别的节点高亮，不重新执行工具。
